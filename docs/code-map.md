## 2. Client Rust workspace · `client_flutter/rust/`

### 2.1. `sinhron_core` — FFI facade (cdylib для Flutter)

**Местоположение:** `client_flutter/rust/Cargo.toml` (root) + `src/`

**Файлы:**

| Файл | Описание |
|---|---|
| `src/lib.rs` | минимальный entry — `mod api;` плюс frb hooks |
| `src/api/mod.rs` | `pub mod simple; pub mod stickers; pub mod transfer;` — поднимает FFI modules |
| `src/api/stickers.rs` | **Стикеры (ADR-049).** Наборы на телефоне (`sticker_pack_save/list/load/delete/move` — зашифрованный файл + список в настройке `sticker_packs`), `sticker_pack_share` (выгрузка один раз, код `sinhron-stickers:`), `sticker_pack_fetch` / `_from_message`, `sticker_meta`, `sticker_fetch`, `net_send_sticker`, `sticker_format_of`; ADR-062: `telegram_pack_info`, `telegram_sticker_files` (пачка файлов разом, ошибки `tg:<code>`) |
| `src/api/backup.rs` | **Копия переписки (ADR-073).** `chat_backup_tag` / `chat_backup_can` / `chat_backup_unlock`, `chat_backup_step` (следующие файлы до лимита в папку; корень — после частей; задача `backup_out`; сбрасывается, если перенос ADR-064 очистил части), `chat_backup_keep` / `chat_backup_reset`, `chat_restore_info` / `chat_restore_start` / `chat_restore_step` (задача `backup_in`, «нужен файл X») / `chat_restore_media` / `chat_restore_adopt` / `chat_restore_clear`. Общий `step_lock` с `transfer.rs` |
| `src/api/transfer.rs` | **Перенос на новое устройство и синхронизация моих устройств (ADR-064).** `device_transfer_status` (sync, карточки прогресса), `device_transfer_step` (один шаг: сначала исходящая задача, потом входящая; `AppTransport` — `/v1/media` + `send_sealed_to_self` только в группу, где одни мои устройства), `device_transfer_start` (вручную «Отправить всё»), `device_transfer_dismiss` (скрыть / остановить), `on_own_message` (из `push_event`: `Transfer` → `accept_offer` / `media_done`, `DeviceSync` → `devsync::apply`; только от меня и только в группе меня), `device_sync_flush` (изменения → `DeviceSync` раз в 20 с; раз в неделю всё; файлы стикерпаков — до сообщения), `device_sync_fetch_packs`. `sync_devices` ставит задачу, когда добавил устройство в «Избранное» (`DeviceSyncReport.transfers`). |
| `src/api/simple.rs` | **главный FFI surface (~900 LOC).** Все pub async/sync fn что-то называются `storage_*`, `net_*`, `sync_*`, `coreVersion` etc. Регенерируется frb-codegen'ом в Dart |
| `src/frb_generated.rs` | **GENERATED** flutter_rust_bridge. **НЕ редактируй вручную.** Регенерируется через `flutter_rust_bridge_codegen generate` |

**Ключевые FFI функции (в `api/simple.rs`):**
- `core_version()` — diagnostics
- `generate_recovery_phrase()`, `validate_recovery_phrase(phrase)`, `derive_identity_fingerprint(phrase)` — BIP-39
- `derive_ed25519_public_hex`, `sign_with_recovery`, `verify_signature` — Ed25519 ops
- `mls_ciphersuite_name`, `mls_smoke_init` — diagnostics
- `storage_init(path, key_hex)`, `storage_save_phrase`, `storage_load_identity`, `storage_wipe_identities` — identity persistence
- `storage_chats_*`, `storage_messages_*` — chat/message CRUD; `storage_chat_set_group_name` — имя группы от участника (ADR-034)
- `net_connect_from_phrase`, `net_send_submit`, `net_send_welcome`, `net_send_encrypted`, `net_next_event`, `net_shutdown` — WS client
- `sync_create_saved_group` — ADR-055: группа «Избранное» из одного этого устройства, объявлена серверу, id в настройке `saved_chat_id`; история для нового устройства несёт флаг `saved` (`send_history`), принимающая сторона — `adopt_saved_chat` (только от себя и если в группе только мои устройства — `SyncClient::is_own_devices_group`)
- `sync_init_from_phrase`, `sync_create_keypackage_b64`, `sync_create_group`, `sync_invite_to_group`, `sync_join_via_welcome`, `sync_publish_keypackage`, `sync_fetch_kp_and_invite`, `sync_fetch_kps_and_invite_people` / `sync_add_group_members` (группы из нескольких человек, ADR-034), `sync_bootstrap_with_server`, `sync_shutdown`, `sync_backup_state`, `sync_restore_state` — MLS layer

**Singletons внутри:**
- `static NET_CLIENT: OnceLock<Mutex<Option<WsClient>>>` — один WS client per process
- `static SYNC_CLIENT: OnceLock<Mutex<Option<SyncClient>>>` — один MLS client per process
- (sinhron_storage's `DB: OnceLock<Mutex<Connection>>` отдельно)

**Gotcha:**
- После любого изменения `simple.rs` запусти `flutter_rust_bridge_codegen generate` иначе Dart bindings будут несвежими — runtime crash.
- Pre-commit hook `scripts/check_frb_drift.sh` ловит это.

- **Схема v16 (ADR-064):** `sync_clock(item, ts, seq, local, deleted)` — часы синхронизации моих устройств (`devsync`); идемпотентно.
- **Схема v17 (ADR-070):** `messages.entities_json` — форматирование текста / подписи (JSON-диапазоны, UTF-16; `[]` — без форматирования, NULL — сообщение старого приложения: маркеры 0.6.0 читаются при показе). Пишут `message_insert` (`NewMessage.entities_json`), `message_apply_edit(…, entities_json, …)`; `message_apply_delete` стирает; `transfer` (`TMessage.entities_json`) переносит; FFI `storage_message_insert` / `storage_message_apply_edit` пересобирают JSON через `entities_from_json` (`stored_entities`).
- **Схема v14:** `peer_avatars(peer_id, jpeg, updated_ts)` — фото из `profile`, перекодированное этим устройством (`peer_avatar_set`, пустое = удалить; FFI `storage_peer_avatar_set` сам вызывает `photo::prepare`, мусор → удаление); `chats.peer_id` — собеседник личного чата (`chat_set_peer`, отдаётся в `chats_list`). Своё фото: `media_avatar_prepare` → настройка `profile_avatar` (base64) → `People.ensureShared`. Dart: `peerAvatarsProvider`, `DsAvatar(image:)`, `ChatPreview.avatar/peerId`.
- **Схема v13:** `chats.mentioned` — непрочитанное упоминание меня (`chat_set_mentioned`; `chat_mark_read` снимает).
- **Схема v12** (ревью): `messages_fts` пересоздаётся с `secure-delete`; соединение — `PRAGMA secure_delete = ON`. Системные строки в `message_insert` не считаются «моим сообщением» (не снимают запрос, не стирают черновик). `chat_unpin_if` (сравнить-и-снять закрепление), `chat_rename_if` (личный чат получает имя собеседника из `profile`, пока у него имя-заглушка). Поиск 1–2 символов — проход со сворачиванием регистра в Rust (Юникод), не `LIKE`.
- **Схема v11:** `chats.request` — запрос на переписку; ставится при входе по Welcome (`NetService._onWelcome` → `storage_chat_set_request`), снимается принятием (`ChatActions.acceptRequest`) или моим сообщением (`message_insert`). Дартовая проверка — `isMessageRequest` (`chat_providers.dart`): её используют квитанции прочтения, «печатает», `People.ensureShared`, отсев звонков; в `ChatViewScreen` — `_RequestBar`.
- **Строка списка:** `chats_list` отдаёт `last_msg_status` (статус моего последнего сообщения, подзапрос по `idx_msgs_chat_ts`) → галочки в `DsChatRow`; «печатает…» — `ChatPreview.asTyping`.
- **Окно правки:** `message_apply_edit` / `message_apply_delete(…, now)` меняют только сообщения не старше `EDIT_WINDOW_SECS` (24 ч; входящим + `LATE_ACTION_GRACE_SECS`). В Dart — `kEditWindow` (`message_actions.dart`), `_Msg.changeable` прячет пункты меню.
- **Схема v10:** `messages_fts` — FTS5 (trigram) по тексту сообщений, триггеры `messages_fts_ai/ad/au`, `fts_reindex`; `messages_search` — индекс от 3 символов, короче — `LIKE`; хит несёт `wire_id`.
- **Схема v9** (`SCHEMA_VERSION`): `peer_names` (имя из `profile`, по ключу личности), `blocked_peers` (локальная блокировка), `chats.profile_sent` (какой мой профиль чат уже знает: раунд, имя, отпечатки фото и «О себе», после `\u0003` — отпечаток участников).
- **Схема v19** (status 213): `message_receipts (wire_id, peer, delivered_at, read_at)` — для «Инфо о сообщении» (`receipts_record` / `receipts_for`, FFI `storage_receipts_record` / `storage_receipts_for`); триггер удаляет строки вместе с моим сообщением.
- **PRAGMA user_version** migration pattern (не `schema_version` table; та была сломана в WU 73 — миграционный код её drop'ает для backward compat).
- **WAL + synchronous=NORMAL** обязательно (Risk #1; iOS background-kill resilience).
- **SQLCipher key**: format `PRAGMA key = "x'<64-hex>'"`. NO password-based KDF; ключ уже derived via HKDF outside.
- Global singleton `DB: OnceLock<Mutex<Connection>>`. Одна connection per process — sequential доступ.

**Gotcha:** `Connection` is `Send + !Sync`. Любая попытка делать async fn ему даёт компайл-tail; в sinhron_storage это OK (мы блокирующие), но через FFI всё проходит через tokio runtime — нужно `spawn_blocking` если станет горячо.

### 2.4. `sinhron_net`

**Назначение:** WebSocket клиент к operator-server'у.

| Файл | Описание |
|---|---|
| `src/lib.rs` | re-exports |
| `src/client.rs` | **WsClient + WsClientConfig.** tokio-tungstenite-based. `wss://` без прокси — `connect_wss` (ADR-072): TCP к адресам `dns::Resolver` по очереди, TLS с именем из URL, адрес с ошибкой TLS — `note_bad`. Reconnect with exp backoff. Auth handshake (Hello → Auth → Ack; the login is bound to the URL's host — `ws_auth_message`, `url_host`, `bind_to_host`, ADR-086). Channel-based send/recv API. `Keepalive` (heartbeat 20 s, background 120 s once the server accepts it via `Heartbeat.next_within_secs`, server-silence 45 s, reply timeout 30 s, backoff) + `start_with_keepalive`; `set_background` / `network_changed` (watch channel `Mode`: the gap switches in-session, a network change reconnects at once and cuts the back-off); `shutdown` stops reconnects (flag). ~750 LOC 0.12.0 (CN-20): к паузе переподключения добавляется случайная доля до четверти (`jitter`), пауза сбрасывается к начальной после устойчивого сеанса (`STABLE_SESSION` 30 с); запись кадра ограничена `keepalive.reply_timeout` (`send_frame_split`); тесты `tests/backoff.rs`, `tests/write_timeout.rs`. |
| `tests/keepalive.rs` | Фейковый WS-сервер в тесте: heartbeat держит тихую сессию, молчащий сервер замечается, шторм из 100 переподключений и 100 циклов start/shutdown без утечки дескрипторов; фон (2026-10-18): длинный промежуток только после согласия сервера, старый сервер — остаётся 20 с, мёртвая связь в фоне — за один heartbeat, смена сети — переподключение сразу и без ожидания back-off |
| `src/dns.rs` | **ADR-072 — адрес нашего сервера, когда DNS телефона врёт.** `Resolver` (`global()`): для наших хостов (`add_our_host` из https/wss-адресов) системный ответ → TLS-проверка (`tls_probe`: SNI + сертификат на наше имя) → запомненный адрес → DoH (`NetBackend::doh`: 1.1.1.1, 8.8.8.8, JSON, `parse_doh_json`) → проверка; `override_ip` / `override_for` (адрес вместо системного — только если тот не прошёл), `note_bad`, `load` / `export` / `set_persist` (JSON для `settings.net_dns_cache`), фоновая перепроверка; `ReqwestDns` — хук reqwest; `Backend` — шов для тестов. 14 тестов |

Сертификаты — `tests/data` (тестовый CA, до 2126) |
| `examples/dns_check.rs` | ADR-072 на настоящей сети: системный ответ, проверка каждого адреса, что выбрал бы резолвер (`cargo run -p sinhron_net --example dns_check -- https://chat.777400777.xyz`) |

### 4.2. Ключевые core/ модули

**`core/providers/core_providers.dart`** (~110 LOC):

**`core/providers/chat_providers.dart`** (~300 LOC):
- `chatsProvider` — FutureProvider<List<StoredChatSummary>>, читает chats table
- `messagesProvider.family<List<StoredMessageSummary>, String>(chatId)` — мессаги для конкретного чата
- `sendMessage(ref, chatId, body)` helper — пишет в SQLite + invalidate'ит providers + отправляет через NetService (MLS-encrypted если group_id_hex chatId, иначе legacy hash)
- `createMlsChat(ref, recipientHex, displayName, httpBase)` — full MLS dance: create_group + fetch_kp_and_invite + send_welcome + chat row upsert + its `peer_id` (2026-11-03: «Написать» находит чат и до `profile`)
- `createMlsGroup(ref, name, memberIdentityHexes, httpBase)` — ADR-034: create_group + `sync_fetch_kps_and_invite_people` (один Commit) + Welcome каждому + строка чата `isGroup` + действие `group_name`; `addGroupMembers(...)` — `sync_add_group_members` + Welcome новым + имя снова. ADR-035 (`message_actions.dart`): `GroupOps` / `groupOpsProvider` (FFI `sync_remove_group_members`, `sync_leave_group_server`, `sync_group_is_active`, `sync_group_admin` — ADR-088), `groupRoleProvider` (`GroupRole.canManage`), `MessageActions.removeMembers / renameGroup / leaveGroup / onGroupCommit` (строки «добавил(а) / удалил(а)» из Commit'а — `action_json` `{by, added, removed}`, запись 231); экран `features/chat_info/group_rename_screen.dart`

**`core/services/net_service.dart`** (~320 LOC):
- `NetService` class, exposed via `netServiceProvider`
- `startFromPhrase({phrase, url})` — sync_init → net_connect_from_phrase (запускает _runEventLoop) → sync_bootstrap / enable_sealed (ожидание ≤ 15 с). Соединение раньше HTTP — баг 2026-10-16 (Wi-Fi → LTE).
- `_runEventLoop()` — polls `netNextEvent`. Routes by `event.kind`: connected/disconnected/push/ack/welcome.
- `_onPush(p)` — chat lookup by exact id (chatId == group_id_hex; a former Saved group → Saved), then storageMessageAppend + invalidate. `undecrypted` frames are dropped (logged).
- `_onWelcome(w)` — sync_join_via_welcome + chat row create.

**`main.dart`** (~100 LOC):
- Boot sequence:
  1. RustLib.init() — load Rust dylib
  2. getApplicationDocumentsDirectory() → dbPath + mlsDbPath
  3. storageInit(path: dbPath, keyHex: '') — chats DB plain (TODO sqlcipher_export migration)
  4. stat mls-state.sqlite for diag
  5. BootDiagnostics override into ProviderScope
  6. runApp

**`app/navigation.dart`** (~1100 LOC):
- AppRoot (ConsumerWidget) — identity-aware routing: persisted identity → ChatList, else splash
- _wire*Builder() — caller-binding pattern для each route с callbacks
- _adaptiveTab / _detail — ADR-076: вкладки в `AdaptiveSplit` (две колонки на iPad), строки открывают справа; `_paneRoute` (Esc закрывает), `_stepChat` (⌥↑/⌥↓), `_openSearch`, `_form` (онбординг колонкой)
- _route() — 180ms easeOut FadeTransition page transition
- _wireSignOutBuilder() — wipe identities + chats + delete mls-state file + invalidate providers
