# Проверка безопасности перед публичным запуском — 2026-11-02 (запись 221)

**Вопрос владельца:** «Проверить все уязвимости, всю систему, как будто завтра я хочу её выпустить для публики».

**Как проверяли.** Пять независимых проверок кода (только чтение): HTTP API сервера; WebSocket и протокол; шифрование и ключи на телефоне; атаки через приложение (ссылки, файлы, уведомления, Android/iOS); развёртывание (Caddy, Docker, coturn, LiveKit, установщик, CI, резервные копии, git). Плюс сканирование библиотек на известные уязвимости (`osv-scanner`: `server/Cargo.lock`, `client_flutter/rust/Cargo.lock`, `client_flutter/pubspec.lock`) и проверка живого сервера только на чтение. Самые серьёзные находки перепроверены вручную по коду — отмечены «✔ проверено».

**Вывод.** Для семьи и друзей (люди, которые доверяют серверу и друг другу) система работает. **Для публики выпускать нельзя**: есть дыры, через которые посторонний может мешать людям или пользоваться сервером, а сервер (или тот, кто его взломает) — незаметно подменить собеседника и читать переписку. Ниже — что исправить до запуска (P0), вскоре после (P1) и потом (P2).

## P0 — исправить до публичного запуска

### Шифрование: сервер может подменить собеседника
1. **Ключ устройства в чате не сверяется с его сертификатом** ✔ проверено. `client_flutter/rust/sinhron_sync/src/identity.rs::identity_of_credential` доверяет 32-байтной «личности» или подписанному сертификату, но не сравнивает их с ключом подписи участника MLS (`leaf.signature_key`). Сервер (или взломщик сервера) подкладывает пакет ключей «Боба» со своим ключом подписи — и становится «Бобом» в чате: читает и пишет от его имени. Сверка кодов безопасности это **не ловит** (сравниваются только личности). То же в группе моих устройств: поддельное «моё устройство» получает перенос истории и синхронизацию. *Исправление:* в каждой проверке участника требовать `signature_key == личность` (старые листья) или `== device_pub` из сертификата; для пакетов ключей контакта — что личность = тот, кого добавляем. Нужна новая версия приложения у всех.
2. **Ключи доставки (sealed sender) не подписаны** — `http_api.rs::fetch_sealed_keys` берёт ключ, который вернул сервер. Сервер подсовывает свой ключ и читает **начало каждого срочного сообщения** (превью до 320 байт для уведомлений) и кто кому пишет, затем пересылает дальше. *Исправление:* подписывать недельный ключ доставки ключом устройства/личности и проверять при получении. **✔ Сделано в записи 236 (ADR-082)** — `mls-identity:4` в `docs/security-review-2026-11.md`; действует, когда обновлены обе стороны и сервер.
3. **Пакеты ключей контакта не проверяются на принадлежность** (`client.rs`, `group.rs`) — даже после п. 1 сервер может отдать вместо пакетов Боба пакеты Мэллори; имя в чате остаётся «Боб». *Исправление:* как в п. 1.

### Сервер: посторонний меняет группы и мешает людям
4. **`POST /v1/groups` без входа** ✔ проверено (две проверки нашли независимо). Добавляет любое устройство в любую группу, в том числе существующую. Посторонний получает зашифрованный поток группы (кто, когда, сколько), пишет в неё мусор, получает токен комнаты звонка, звонит людям в обход блокировок, ломает «карточку чата» и замораживает группу (п. 5). *Исправление:* подпись создателя; добавлять участников только в новую группу или в ту, где подписавший уже участник; дальше — состав по Commit/Welcome.
5. **«Заморозка» группы номером эпохи** (`ws.rs`, `SET current_epoch = $2 + 1 WHERE current_epoch <= $2`). Участник (или посторонний через п. 4) шлёт Commit с огромным номером — после этого любые изменения группы отклоняются навсегда. *Исправление:* принимать только `commit_epoch == current_epoch`.
6. **Выкачивание пакетов ключей без входа** ✔ проверено (`keypackages.rs::consume`). Кто угодно опустошает запас пакетов человека — его нельзя добавить в новый чат и нельзя привязать ему новое устройство. *Исправление:* подписанный запрос зарегистрированного, лимиты на вызывающего и на цель, «последний» пакет.
7. **Отказ в обслуживании (память, диск)**:
   - сообщения WebSocket до 64 МБ, очереди на соединение без предела, Resume без лимита → сервер можно уронить по памяти;
   - таблицы лимитов никогда не чистятся (`gc_idle` только в тестах), ключи пишутся до проверки → память растёт от запросов **без входа**;
   - лимит регистрации — на ключ, который выбирает сам нападающий (каждая новая пара ключей — новый лимит);
   - Welcome без лимита и без размера, хранится год;
   - медиа без квоты на человека, лимит обходится сменой регистра букв ключа.
   *Исправление:* `max_message_size` ~256 КБ–1 МБ, ограниченные очереди, лимиты на Resume/Welcome, регистрация по IP + общий потолок, чистка таблиц лимитов, квота медиа на человека.
8. **Сервер звонков как бесплатный ретранслятор** ✔ проверено. `/v1/call/turn` выдаёт данные TURN на сутки любому новому ключу (не проверяет, что он зарегистрирован); у coturn нет квот и нет запрета IPv6-адресов внутренних сетей. *Исправление:* только зарегистрированным, лимиты, `user-quota`/`total-quota`/`max-bps`, `denied-peer-ip` для IPv6, короче срок.

### Живой сервер (проверено на сервере, только чтение)
9. **SSH пускает root по паролю** (`permitrootlogin yes`, `passwordauthentication yes`) — самая частая дверь для взлома серверов. *Исправление:* вход только по ключу; установщик должен делать это сам.
10. **Журнал Caddy хранит IP и адреса всех запросов без предела** (уже 17 МБ, ротации нет) — готовый архив «кто, когда, откуда»; расходится с обещанием «без администратора IP не храним». *Исправление:* журнал только ошибок, ротация логов Docker (`max-size`).
11. **Резервные копии**: дамп базы и медиа **не зашифрованы** (зашифрован только `.env`), архивы медиа на сервере читаются любым пользователем (`rw-r--r--`). *Исправление:* GPG для дампа и медиа, права 600.

### Приложение
12. **Android: после звонка с заблокированного экрана Sinhron остаётся виден поверх блокировки** ✔ проверено (`MainActivity.kt`: `setShowWhenLocked(true)`, обратно не выключается; любое приложение может включить это намерением `SHOW_CALL`). Если блокировка приложения выключена — чаты видны любому, кто взял телефон. *Исправление:* выключать после звонка; действия звонка — через не экспортируемую активность.

## P1 — вскоре после запуска

- **Добавления в группу по Commit не показываются и не проверяются** (`group.rs`): участник с изменённым приложением тихо добавляет людей/устройства; после ухода создателя «админом» становится случайный новичок.
- **Отозванное устройство сохраняет общие ключи аккаунта** (ключ облачной копии, корни доставки и доступа) — читает будущие копии в iCloud/Drive при доступе к облаку. Нужна смена ключей при отзыве.
- **Поддельное уведомление «от мамы»**: расширение уведомлений iOS берёт название чата из присланного id группы и не проверяет, что отправитель в этом чате.
- **Ссылка-приглашение может вести на любой сервер, даже без шифрования (`http://`)**, и экран приглашения стучится туда ещё до нажатия (утечка IP). Только `https`, без IP-адресов, проверка — после нажатия.
- **«Был(а) в сети» видно любому, кто знает ключ** (`GET /v1/devices` без входа отдаёт `last_seen_at`), хотя по умолчанию это скрыто (ADR-031). Плюс ответы «зарегистрирован ли ключ» без входа.
- **Подписи не привязаны к серверу**: злой сервер из ссылки-приглашения может переслать вызов и войти на настоящий сервер от имени человека (вход, подтверждения действий в течение 60 с).
- **Регистрационное доказательство статично и не покрывает устройство** — «призрачное» устройство к чужому аккаунту на другом сервере.
- **Перехват push-токена** другого человека (`push_tokens.rs`), **заблокированный всё равно звонит в открытое приложение** (`access_keys.rs`), **активные звонки не чистятся** (группа «занята» до перезапуска).
- **Полные id групп и граф «кто кого пригласил» в журналах сервера** (`ws.rs` info-строки).
- **Соседний сайт в Caddy (`/etc/sinhron/caddy-sites`) может прочитать TLS-ключи Sinhron** (общий `/data`) — в threat-model сказано обратное; исправить текст и изолировать соседей.
- **Секреты LiveKit и TURN видны в командной строке процессов** (`ps`), приложение ходит в Postgres суперпользователем, образы старые (`postgres:16.4` с исправленными позже CVE), сервер не отказывается стартовать с тестовыми секретами из `.env.example`.
- **Обновления сервера** — `git pull` ветки `main` от root без проверки подписи.
- **Библиотеки** (сканер): в сервере и приложении устаревшие `rustls` (0.23.40 → 0.23.46), `rustls-webpki`, `time` (CVSS 6.8), `bytes`, `tokio`, `tracing-subscriber`, `anyhow`; в приложении `libcrux-secrets` / `libcrux-sha3` через `hpke-rs` (MLS) — ошибка «постоянного времени» на ARM (телефоны) и неверный вывод SHAKE; нужно обновить `openmls_rust_crypto`/`hpke-rs`. Флаги сканера про `rsa`, `quinn-proto`, `libcrux-aesgcm/kem/chacha` — эти пакеты в сборку **не попадают** (только в lock-файле). Dart-пакеты — чисто.
- **24 слова**: нет `FLAG_SECURE` на Android (снимки экрана/запись), слова кладутся в обычный буфер обмена (Universal Clipboard).
- **Картинка-«бомба»** (стикер/аватар 16k×16k) роняет приложение при открытии чата.

## P2 — потом

48-битный «адрес» для сверки при приглашении; QR привязки не показывает, чей аккаунт пришёл; откат облачной копии; диагностический журнал в открытом файле; карточка превью ссылки обходит список разрешённых схем; изменяемый PendingIntent ответа; самообновление без предела размера загрузки; release-сборка молча подписывается отладочным ключом без `key.properties`; адрес звонков по умолчанию `http://localhost:8080`; символы направления текста в именах файлов; zip стикеров доверяет размеру из заголовка; ответы и heartbeat идут на все соединения человека; неверный отправитель в Submit; включённый по умолчанию legacy-push от незнакомцев; публичный ntfy; нет лимитов размера запроса в Caddy; файлы `--partial` видны в `/download/`; контейнеры без `cap_drop`/`no-new-privileges`; действия CI не закреплены по SHA; пароль подписи APK в командной строке.

## Что в порядке

Секретов в git нет (ни сейчас, ни в истории). SQL везде параметризован, пути медиа защищены от `..`. Вызов при входе — свежие 32 случайных байта, домены подписей разделены. Отозванное устройство отключается от WebSocket. Push через Apple/Google не несёт текста и групп в открытом виде. Postgres слушает только 127.0.0.1, сервер работает не от root, брандмауэр по умолчанию всё закрывает, тестовых секретов на сервере нет. Самообновление Android проверяет SHA-256, имя пакета и сертификат. Ключи в Keychain (`ThisDeviceOnly`) и Android Keystore, база — SQLCipher. Ссылки в сообщениях открываются только через подтверждение. Сравнение секретов на сервере — за постоянное время.
